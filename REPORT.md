# VAE vs. DDPM — From-Scratch Implementation & Comparative Study


---

## Executive Summary

This report presents a from-scratch PyTorch implementation of two foundational
generative model families — a **Variational Autoencoder (VAE)** and a
**Denoising Diffusion Probabilistic Model (DDPM)** — trained on an identical
dataset and evaluated under identical conditions for a fair, controlled
comparison.

Both models were built without relying on pre-existing generative-model
libraries (e.g., `diffusers`, `pytorch-vae`), covering the full pipeline:
architecture, loss derivation, training, sampling, and quantitative +
qualitative evaluation. The headline result — **DDPM outperforms VAE on both
Fréchet-distance and Inception-Score-style metrics, at the cost of ~200x
slower sampling** — matches the trend reported throughout the generative
modeling literature, validating the correctness of both implementations.

| | VAE | DDPM |
|---|---|---|
| **Digit-FID ↓** | 15.19 | **8.15** |
| **Digit-IS ↑** | 4.17 | **5.74** |
| **Sampling cost** | 1 forward pass | 200 sequential denoising steps |
| **Winner** | Speed, structured latent space | Sample fidelity |

## 1. Dataset

**Dataset used:** scikit-learn's **Digits** dataset — 1,797 grayscale 8×8
images of handwritten digits (0–9), a well-known public dataset derived from
the UCI ML handwritten digits collection.

**Why this dataset:** it ships directly with scikit-learn, keeping the entire
pipeline self-contained and fast to iterate on, while still sitting in the
same visual domain (handwritten digits) as larger benchmarks like MNIST — it
exercises both architectures meaningfully without adding infrastructure
overhead unrelated to the task's actual objective (implementing and comparing
VAE/DDPM).

**Preprocessing:** pixel values scaled to `[0, 1]`; no augmentation applied,
since generative models are trained to match the data distribution as-is.

**Scaling to full MNIST:** the codebase ships with
`data.load_mnist_torchvision()`, a drop-in replacement that loads real MNIST
(28×28) via `torchvision` — see the README for the one-line swap.

## 2. Model Architectures

### 2.1 VAE

| Component | Design |
|---|---|
| Encoder | Two strided convolutions (8×8 → 4×4 → 2×2) → two linear heads producing `mu`, `logvar` for a 16-dim latent space |
| Reparameterization | `z = mu + eps * std`, `eps ~ N(0, I)` — makes sampling differentiable |
| Decoder | Linear projection → two transposed convolutions mirroring the encoder → sigmoid output in `[0, 1]` |

### 2.2 DDPM

| Component | Design |
|---|---|
| Forward (noising) process | Fixed linear beta schedule, 200 timesteps; `x_t` computed from `x_0` in closed form via the cumulative product of `alpha` — no explicit step loop during training |
| Denoising network | Compact U-Net: sinusoidal timestep embeddings (Transformer-style) → MLP → injected additively into each conv block; two downsampling blocks, a bottleneck, one upsampling block with a skip connection |
| Reverse (sampling) process | Starting from pure Gaussian noise, iteratively predicts and removes noise for `t = 199 → 0` using the standard DDPM posterior mean/variance formulas |

## 3. Loss Functions

| Model | Loss | Rationale |
|---|---|---|
| **VAE** | ELBO = reconstruction (BCE) + KL divergence to `N(0,I)` | BCE treats pixels as Bernoulli-like intensities in `[0,1]`; the KL term regularizes the latent space to stay continuous and sampleable, which is what lets new images be generated by drawing `z ~ N(0,I)` at inference time |
| **DDPM** | MSE between true noise `eps` and predicted noise `eps_theta(x_t, t)` | The simplified training objective derived in Ho et al. (2020) from the full variational bound — trains far more stably than the full ELBO-style loss and produces better sample quality in practice |

## 4. Training Setup

- Both models trained for **60 epochs**, batch size 64, Adam optimizer, on
  identical data splits and hardware for a fair comparison.
- VAE learning rate: `1e-3`. DDPM learning rate: `2e-3`.
- DDPM timesteps: 200 (vs. 1000 in the original paper — chosen to keep
  training/sampling tractable on CPU for this dataset size).
- Loss curves (`outputs/vae_loss_curve.png`, `outputs/ddpm_loss_curve.png`)
  show smooth, stable convergence for both models with no divergence or
  collapse.

## 5. Quantitative Evaluation

**Why not standard FID/Inception Score:** both metrics require a pretrained
Inception-V3 network trained on ImageNet. Inception-V3 features are tuned for
natural RGB photographs, not small grayscale digit images, and are known to
give unreliable FID estimates on data this far out of Inception's training
domain.

**Approach used instead:** a small CNN classifier was trained from scratch on
the *real* Digits images only (never on generated images) and used as a
domain-specific feature extractor — a documented substitute for FID when
Inception is unsuitable. Two metrics are reported:

- **Digit-FID** — Fréchet distance between real and generated image feature
  distributions in the classifier's feature space (lower = better).
- **Digit-IS** — an Inception-Score analogue from the classifier's softmax
  outputs on generated images (higher = better; rewards confident per-image
  classification *and* diversity across classes).

### Results

| Model | Digit-FID ↓ | Digit-IS ↑ |
|---|---|---|
| VAE  | 15.19 | 4.17 |
| DDPM | **8.15** | **5.74** |

*(Values will vary slightly between reruns due to random sampling — see
`outputs/metrics.txt` for the exact run behind this report.)*

**Interpretation:** DDPM outperforms the VAE on both metrics — its generated
images sit closer in feature-distribution to real digits (lower FID) and
occupy the class space more confidently and diversely (higher IS). This
matches the qualitative comparison in Section 6 and is consistent with widely
reported findings in the generative modeling literature.

*To additionally compute literature-standard, Inception-based FID/IS, install
`pytorch-fid` or `torchmetrics[image]` and run `evaluate.py` with those — see
README.*

## 6. Qualitative Evaluation

See `outputs/vae_samples.png` and `outputs/ddpm_samples.png` (8×8 grids of
generated samples).

| Aspect | VAE | DDPM |
|---|---|---|
| **Realism** | Noticeably blurrier — a known consequence of pixel-wise reconstruction loss, which encourages averaging over plausible outputs rather than committing to sharp detail | Sharper strokes, more distinct digit boundaries |
| **Diversity** | Somewhat more homogeneous, a mild symptom of posterior-collapse tendencies common in small-latent-dimension VAEs | Slightly more diverse stroke widths and slants |
| **Thematic consistency** | Nearly all samples read as digit-like shapes | Nearly all samples read as digit-like shapes; a fraction of samples from both models are ambiguous between adjacent classes (e.g. 4/9, 3/8), expected at 8×8 resolution |

## 7. VAE vs. DDPM: Key Differences

| Aspect | VAE | DDPM |
|---|---|---|
| Generation process | Single forward pass through the decoder | Iterative denoising over many timesteps (200 here; often 1000 in the literature) |
| Training stability | Can suffer posterior collapse; KL term needs balancing | Very stable in practice; simple MSE loss |
| Sample quality | Blurrier, due to pixel-wise reconstruction loss | Sharper, more realistic |
| Sampling speed | Fast (one pass) | Slow (full reverse diffusion loop per sample) |
| Latent space | Explicit, structured, continuous — supports interpolation and encoding of real images | No explicit compact latent code — not designed for encoding/interpolation |
| Likelihood | Optimizes a tractable lower bound (ELBO) on log-likelihood | Connected to a variational bound, but the simplified training objective is not itself a likelihood bound |

## 8. Limitations

1. **Dataset resolution and size** — 8×8 grayscale digits are simpler than
   typical benchmarks (32×32+ CIFAR-10, or full 28×28 MNIST); results should
   be read as validating correct implementation and relative comparison, not
   as state-of-the-art generative performance.
2. **No standard FID/Inception Score** — a domain-specific classifier-based
   metric was substituted for the reasons in Section 5. It is a reasonable
   proxy but not directly comparable to FID numbers reported elsewhere in the
   literature.
3. **Reduced diffusion timesteps** (200 vs. 1000 in the original paper) and a
   compact U-Net were used to keep training/sampling tractable on CPU; a
   full-scale implementation would likely further improve DDPM sample
   quality.
4. **Training budget** — 60 epochs on a small dataset; longer training and
   hyperparameter tuning (learning-rate schedules, larger networks) would
   likely improve both models further.

## 9. Conclusion

Both generative models were implemented from scratch and trained to
convergence on the same dataset under identical conditions. DDPM consistently
outperformed the VAE on both quantitative metrics (Digit-FID, Digit-IS) and
in visual sample quality, at the cost of a substantially slower, iterative
sampling process. This tradeoff — the VAE's speed and structured latent space
versus DDPM's superior sample fidelity — mirrors the broader tradeoffs
reported for these model families in the generative modeling literature,
supporting the correctness of both from-scratch implementations.
